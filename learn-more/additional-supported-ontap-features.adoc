= ASA r2 システムでサポートされる一般的なONTAP機能
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ASA r2システムは合理化されたバージョンのONTAPを実行するため、多くの一般的なONTAPタスクとSystem Managerの機能を他のONTAPシステムと同様に実行できます。

共通の機能の詳細については、次のONTAPドキュメントを参照してください。



[[autosupport]]
== AutoSupport

ONTAP 9.20.1以降では、AutoSupportがHTTPsプロトコルではなくSMTPプロトコル用に構成されている場合、AutoSupportが無効になっているにもかかわらずお客様やパートナーの電子メール受信者が設定されたままになっている場合、およびDNSの問題によりAutoSupportの送信が失敗した場合に、System ManagerはAutoSupportアラートを表示します。

link:https://docs.netapp.com/us-en/ontap/system-admin/manage-autosupport-concept.html["AutoSupport に関する詳細情報"^]。



[[data-protection]]
== データ保護

ASA r2 システムでサポートされている一般的なデータ保護機能の詳細について説明します。



[[clustered-external-key-servers]]
=== クラスタ化された外部キーサーバー

ストレージVM上で、クラスタ化された外部キー管理サーバーへの接続を構成できます。クラスタ化されたキーサーバーを使用すると、ストレージVM上にプライマリキーサーバーとセカンダリキーサーバーを指定できます。キーを登録する際、ONTAPはまずプライマリキーサーバーを試行し、操作が成功するまでセカンダリサーバーを順次試行することで、重複キーの発生を防ぎます。

link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/configure-cluster-key-server-task.html["クラスタ化された外部キーサーバーの構成方法を学ぶ"^]。



[[external-key-management-for-encryption-at-rest]]
=== 保存時の暗号化のための外部キー管理

1つ以上のKMIPサーバを使用して、暗号化されたデータにアクセスする際にクラスタで使用するキーを安全に保管できます。

ONTAP 9.20.1以降では、データストレージVMで外部キーマネージャを有効にすると、ONTAPは、そのストレージVMのボリューム暗号化キーを管理者スコープのキーマネージャから新しいデータストレージVMのキーマネージャに自動的に移行します。これにより、外部キー管理への移行が簡素化され、標準ワークフローにおける別途の手動移行手順が不要になります。

* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-hw-task.html["外部キー管理の有効化"^]。
* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-nve-task.html["外部キー管理（NVE）を有効にする"^] 。




[[data-security]]
== データセキュリティ

ASA r2 システムでサポートされている一般的なデータ セキュリティ機能の詳細について説明します。



[[administrator-access-management]]
=== 管理者アクセス管理

管理者に割り当てられた役割によって、管理者が実行できる機能が決まります。System Managerは、クラスタ管理者とストレージVM管理者向けに、あらかじめ定義された役割を提供します。管理者アカウントを作成する際に役割を割り当てることも、後から別の役割を割り当てることもできます。

link:https://docs.netapp.com/us-en/ontap/task_security_administrator_access.html["System Manager を使用して管理者アクセスを管理する方法を学びます"^]。



[[client-authentication-and-authorization]]
=== クライアント認証と許可

ONTAPでは、標準的な手段を使用して、クライアントや管理者によるストレージへのアクセスを保護し、またウイルスから守ります。保存データの暗号化やWORMストレージでは、高度なテクノロジも使用できます。ONTAPでは、信頼できるソースでIDを検証してクライアント マシンおよびユーザを認証します。ユーザのクレデンシャルとファイルまたはディレクトリに対して設定されているアクセス許可を比較し、ユーザにファイルやディレクトリへのアクセスを許可します。

link:https://docs.netapp.com/us-en/ontap/concepts/client-access-storage-concept.html["クライアントの認証と承認について学ぶ"^] 。



[[fc-sp-3-authentication-and-encryption]]
=== FC-SP-3認証および暗号化

ONTAP 9.20.1以降、ONTAPはASA r2システムのBroadcomセキュアHBAでのFibre Channel Security Protocol 3（FC-SP-3）認証および暗号化をサポートします。FC-SP-3のサポートにより、T11 Fibre Channelセキュリティ標準に準拠しながら、FCおよびNVMe/FC SANホストとONTAPストレージシステム間で転送中のデータを保護する、ハードウェアレベルのエンドツーエンドの暗号化とデバイス認証が可能になります。

* link:https://docs.netapp.com/us-en/ontap/san-admin/fc-sp-3-security-support.html["FC-SP-3認証と暗号化について"^]。




[[multi-admin-verification-mav]]
=== マルチ管理者認証（MAV）

ONTAP 9.20.1以降では、MAV承認グループには、個々の管理者に加えて、IDプロバイダ（IdP）、Active Directory（AD）、およびLDAP（nsswitch）グループを承認者として含めることができます。サポートされるグループの種類には、Entra ID、ADFS、ADドメイングループ、およびLDAPグループが含まれます。IdP、AD、またはLDAPディレクトリでのユーザーの追加や削除で、MAV構成を変更する必要はありません。link:https://docs.netapp.com/us-en/ontap/multi-admin-verify/index.html["MAVの詳細"^]。



[[oauth-2-0-authentication]]
=== OAuth 2.0認証

Open Authorization（OAuth 2.0）フレームワークを使用して、 ONTAPクラスターへのアクセスを制御できます。  OAuth 2.0 は、署名されたアクセス トークンを使用して、保護されたリソースへのアクセスを制限および制御します。

link:https://docs.netapp.com/us-en/ontap/authentication/overview-oauth2.html["OAuth 2.0認証について学ぶ"^] 。



[[saml-authentication-and-administrator-access]]
=== SAML認証と管理者アクセス

Web サービスに対して Security Assertion Markup Language (SAML) 認証を構成して有効にすることができます。  SAML は、Active Directory や LDAP などのディレクトリ サービス プロバイダーではなく、外部 ID プロバイダー (IdP) によってユーザーを認証します。

link:https://docs.netapp.com/us-en/ontap/system-admin/configure-saml-authentication-task.html["SAML認証の設定方法を学習します"^]。



[[snmp]]
=== SNMP

ONTAP 9.20.1以降、ONTAPはSNMPv3ユーザーに対するSHA-512認証をサポートしています。この機能強化により、外部SNMPクライアントおよびスイッチ監視（SHA-512認証を必要とするスイッチを含む）において、より強力なSNMPv3認証を使用できるようになります。

* link:https://docs.netapp.com/us-en/ontap/networking/configure_snmpv3_users_in_a_cluster.html["SNMPv3ユーザーの設定方法"^]。
* link:https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["スイッチでSNMPv3を設定する方法"^]。




[[tls-hardware-offload]]
=== TLSハードウェアオフロード

サポートされているイーサネットカードに、クラスタ全体のトランスポート層セキュリティ（TLS）の暗号化と復号化をオフロードできます。これにより CPU 負荷が軽減され、TLS を使用するシステムのパフォーマンスが向上します。

link:https://docs.netapp.com/us-en/ontap/networking/configure-tls-offload.html["TLS ハードウェアオフロードの設定方法"^]。



[[networking]]
== ネットワーク

ASA r2 システムでサポートされている一般的なネットワーク機能の詳細について説明します。



[[fips-compliance]]
=== FIPS準拠

ONTAPは、すべてのSSL接続において、連邦情報処理標準（FIPS）140-2に準拠しています。ONTAP内で、SSL FIPSモードのオン/オフを切り替えたり、SSLプロトコルをグローバルに設定したり、RC4などの脆弱な暗号を無効にしたりできます。

ONTAP 9.18.1 以降では、SSL でポスト量子コンピューティング暗号化アルゴリズムがサポートされます。これらのアルゴリズムは、将来の潜在的な量子コンピューティング攻撃に対する追加の保護を提供し、SSL FIPS モードが無効になっている場合に利用できます。

* link:https://docs.netapp.com/us-en/ontap/networking/configure_network_security_using_federal_information_processing_standards_fips.html["すべてのSSL接続にFIPSを構成する方法を学ぶ"^]。




[[link-aggregation-groups-lags]]
=== リンク アグリゲーション グループ（LAG）

インターフェイス グループ（別名リンク アグリゲーション グループ[LAG]）は、同じノード上の2つ以上の物理ポートを1つの論理ポートに組み合わせて作成します。論理ポートを使用すると、耐障害性と可用性が向上し、負荷も共有できます。

link:https://docs.netapp.com/us-en/ontap/networking/combine_physical_ports_to_create_interface_groups.html["リンクアグリゲーショングループについて学ぶ"^]。



[[performance]]
== Performance

ASA r2システムでサポートされている一般的なパフォーマンス機能の詳細については、こちらをご覧ください。



[[modify-default-settings-that-control-automatic-qos-throughput-ceiling-increases]]
=== QoS スループット上限の自動増加を制御するデフォルト設定を変更します

適応型および非適応型のQoSポリシーグループは、短期的なパフォーマンス向上要求に対応するため、デフォルトではワークロードのスループット上限を1秒間、一時的に50%増加させます。ONTAP 9.19.1以降では、これらの設定を変更できます。ONTAP 9.18.1以前のバージョンでは、これらの設定を変更することはできません。

link:https://docs.netapp.com/us-en/ontap/performance-admin/guarantee-throughput-qos-task.html["QoS スループット上限の詳細"^]。



[[ipspace-tcp-performance]]
=== IPspaceのTCPパフォーマンス

ONTAP 9.19.1以降、ONTAPはPRRとRACKという2つの損失回復機能をONTAP TCPスタックに統合することで、損失が多く遅延の大きいWANリンク上のTCPデータ転送パフォーマンスを向上させます。PRRはすべてのネットワークに適しており、デフォルトで有効になっています。RACKは、リンク速度が約25 Gigabits/secondの輻輳したネットワークに適しており、デフォルトでは無効になっています。

link:https://docs.netapp.com/us-en/ontap/networking/improve-tcp-wan-performance.html["PRRとRACKを使用してTCP WANパフォーマンスを向上させる方法の詳細"^]。



[[san-configuration]]
== SANの構成

ストレージ エリア ネットワーク（SAN）は、iSCSIやFCなどのSAN転送プロトコルを介してホストに接続されるストレージ ソリューションで構成されます。1つ以上のスイッチを介してホストにストレージ ソリューションを接続するように、SANを構成できます。iSCSIを使用している場合は、スイッチを使用せずにホストにストレージ ソリューションを直接接続するように、SANを構成することもできます。



[[san-direct-attachment]]
=== SAN ダイレクトアタッチメント

ONTAP 9.19.1以降、FCスイッチは、FCおよびFC-NVMeホストとONTAPストレージ間の接続を確立するために必要ありません。ホストは、ASA r2システムのFCアダプタポートに直接接続できます。ダイレクト接続機能は、シンプルさが重要なリモートサイトやハイブリッド環境において特に有用です。

* link:https://docs.netapp.com/us-en/ontap/san-config/configure-fc-nvme-hosts-ha-pairs-reference.html#direct-attach-fc-and-fc-nvme-configurations["SAN ダイレクトアタッチメントの詳細"^]。




[[san-protocols]]
== SANプロトコル

ASA r2 システムは、すべての SAN プロトコル (iSCSI、FC、NVMe/FC、NVMe/TCP) をサポートします。

* link:https://docs.netapp.com/us-en/ontap/san-admin/san-host-provisioning-concept.html["iSCSIプロトコルの詳細"^]。
* link:https://docs.netapp.com/us-en/ontap/san-admin/san-provisioning-fc-concept.html["ファイバーチャネル（FC）プロトコルの詳細"^]。
* link:https://docs.netapp.com/us-en/ontap/concept_nvme_provision_overview.html["NVMeプロトコルについて学ぶ"^]。
+
** link:https://docs.netapp.com/us-en/ontap/san-admin/nvme-copy-offload.html["NVMeコピーオフロードの設定方法を学ぶ"^]。
+
ONTAP 9.18.1以降、ONTAPはNVMeコピー オフロードをサポートしています。NVMeコピー オフロードを使用すると、NVMeホストはコピー処理を自身のCPUからONTAPストレージ コントローラのCPUにオフロードできます。ホストは、アプリケーション ワークロード用にCPUリソースを確保しながら、あるNVMeネームスペースから別のNVMeネームスペースへデータをコピーできます。

** link:https://docs.netapp.com/us-en/ontap/san-admin/enable-space-allocation.html["NVMeのスペース割り当て（アンマップ）の詳細"^]。
+
ONTAP 9.16.1 以降では、NVMe 名前空間のスペース割り当て解除 (「ホール パンチ」または「アンマップ」とも呼ばれます) がデフォルトで有効になっています。スペース割り当て解除機能により、ホストはネームスペースで使用されていないブロックの割り当てを解除してスペースを再利用できます。







[[storage-efficiency]]
== Storage Efficiency

ストレージ効率とは、ストレージ リソースを最適化し、無駄なスペースを最小限に抑え、書き込まれたデータの物理的なフットプリントを削減することで、ストレージ システムが利用可能なスペースをどれだけ効率的に使用しているかを示す指標です。

ONTAPは、ストレージ使用量の最適化とコスト削減に役立つ、さまざまなストレージ効率化技術を提供します。

link:https://docs.netapp.com/us-en/ontap/concepts/storage-efficiency-overview.html["ONTAP ストレージ効率化テクノロジの詳細"]。



[[data-reduction-rate-drr]]
=== データ削減率（DRR）

ONTAP 9.20.1以降では、ストレージ効率のデータ削減率（DRR）は、削減可能なデータのみを含めることで、ONTAPのストレージ効率によるスペース削減量をより正確に評価できます。ONTAP 9.19.1以前では、DRRには削減可能なデータと削減不可能なデータの両方が含まれます。

link:https://docs.netapp.com/us-en/ontap/concepts/capacity-measurements.html["ONTAPが使用済みストレージをレポートする方法の詳細"^]。



[[global-deduplication]]
=== グローバル重複排除

ONTAP 9.19.1以降、_グローバル重複排除_は、ストレージユニットレベルのlink:https://docs.netapp.com/us-en/ontap/concepts/deduplication-concept.html["既存の ONTAP 重複排除によるスペース削減効果"^]をストレージの可用性ゾーン（SAZ）全体に拡張します。SAZ内のすべてのストレージユニットにわたる重複データブロックを排除することで、ストレージ効率を大幅に向上させ、総所有コストを削減できます。グローバル重複排除は、機能ライセンスを必要とせず、デフォルトで有効になっており、既存のストレージ効率化テクノロジとシームレスに統合され、パフォーマンスへの影響を最小限に抑えながら透過的に動作し、管理設定も不要です。



[[system-manager]]
== System Manager

System Managerでは、さまざまな操作、オブジェクト、および情報トピックを検索できます。表示されたデータの中から特定のエントリを検索することもできます。

link:https://docs.netapp.com/us-en/ontap/task_admin_search_filter_sort.html["システム マネージャーで情報を検索、フィルタリング、並べ替える方法を学びます"^]。



[[user-password-expiration-alerts]]
=== ユーザーパスワード有効期限切れアラート

ONTAP 9.20.1以降では、ユーザーアカウントに関連付けられたロールでパスワードの有効期限アラートが設定されている場合、パスワードの有効期限が切れる14日前から、ログイン直後にSystem Managerのページ上部にバナーアラートが表示されます。アラートはユーザーがログインするたびに更新され、パスワードの有効期限が切れるまでの残り日数が表示されます。管理者ロールを追加または編集する際に、有効期限アラートを設定できます。

link:https://docs.netapp.com/us-en/ontap/authentication/configure-password-expiry-alerts.html["System Managerでパスワードの有効期限アラートを設定する方法について説明します。"^]。
