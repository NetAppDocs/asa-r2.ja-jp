= ストレージVMの移行後にクライアントを手動で切り替える
:allow-uri-read: 


クラスタ間のストレージVM移行中、クライアントI/Oはデスティネーション クラスタに移行し、ソースクラスタ上のストレージVMは自動的に削除されます。移行中にソースストレージVMの自動カットオーバーと削除を無効にすることを選択した場合、移行ステータスが*Ready for source cleanup*に達したあとに、これらの手順を手動で実行する必要があります。



[[manually-cut-over-clients-after-a-storage-vm-migration]]
=== ストレージVMの移行後にクライアントを手動で切り替える

ストレージVMのクラスタ間移行中にクライアントの自動切り替えを無効にした場合、移行関係が切り替え準備完了となった後、手動で切り替えを実行して、移行先のストレージVMがクライアントにデータを提供できるようにしてください。

.タスクの内容
このタスクはデスティネーション クラスタから実行してください。

.手順
. クライアント カットオーバーを手動で実行します。
+
[source, cli]
----
vserver migrate cutover -vserver <storage_VM_name>
----
. カットオーバー操作が完了したことを確認します。
+
[source, cli]
----
vserver migrate show
----


.結果
データは、デスティネーション クラスタ上のストレージVMからクライアントに提供されています。

.次の手順
これで、ソースクラスタからストレージVMを削除する準備が整いました。



[[manually-remove-a-storage-vm-after-migration]]
=== 移行後にストレージVMを手動で削除する

クラスタ間ストレージVM移行中に自動ソースクリーンアップを無効にした場合、移行完了後に、ストレージVMをソースクラスタから削除してストレージ領域を解放してください。

.開始する前に
クライアントは、デスティネーション クラスタからデータを提供している必要があります。

.手順
. ソースクラスタから、ソースストレージVMの状態が「ソースクリーンアップの準備完了」であることを確認します：
+
[source, cli]
----
vserver migrate show
----
. ソースストレージVMを削除します：
+
[source, cli]
----
vserver migrate source-cleanup -vserver <storage_VM_name>
----


.結果
ソースクラスタ上のストレージVMが削除されます。
